## 1. 今回確定した目的と訂正
本は単品レシピの寄せ集めではなく、週間献立と、それを一括で作る材料・共通仕込み・取り分け・仕上げを一組で示す。利用者は基本の一週間を受け取り、食べない料理の差替えや外食による除外など、必要な箇所だけを直す。その結果から材料と工程を組み直す。

以前の「料理ごとに規定量を作る」という回答を、各料理に本の週間出来高と同じ固定最小ロットがある、と解釈したのは誤り。資料の週間予定出来高、料理別の1回使用分、機器が要求する最小調理量は別の値である。単品レシピの追加入手をこの計画の開始条件にしない。

既存WORKFLOWには共通ベースを共同で計画する要件があったが、実装はセット全体の切上げを採用し、実利用に必要な可変展開へ達していなかった。今回をすべて新しい要求の追加と扱わず、初期のBOM目的を実装へ反映するための修正とする。

## 2. 利用者の操作
| 場面 | 利用者の操作 | アプリの責務 |
| --- | --- | --- |
| 週を始める | 本をもとにした基本献立を確認 | 登録済み週間テンプレートを初期案として提示 |
| 調整する | 料理の差替え・追加・除外、外食の指定 | 通常一覧とお気に入りから選択し、変更後の需要を集計 |
| 作るものを見る | 必要なら予定量/調理日を調整 | 使う日に利用可能な完成品だけを引当し、不足から共同の仕込み量を計画 |
| 買い物する | 必要分が家にある食材をチェック | 材料必要量と買う対象を表示し、メモへコピー |
| 作る | 日別の共通工程に沿って進める | 下処理・加熱・配分・仕上げ・小分けを一つの作業順で表示 |
| 記録する | 実出来高、実使用、必要な訂正 | 完成品のロット/期限と今後の不足を更新 |

未開始の週はテンプレートを見せ、採用時に家庭の計画へ保存する。既存週へ更新だけでテンプレートを流し込まない。既存予定の差替えは対象を示す操作とし、実績付きの食事/履歴/在庫を上書きしない。前週コピーと空欄からの作成も残せるが、全食を一から入力することを標準の入口にしない。

お気に入りは差替え候補の絞込みであり、自動採用や自動除外の指示ではない。お気に入りから選べる条件も、通常一覧と同じレシピ/工程定義の有無で判定する。元の週にない登録料理も、定義と調理条件が揃っていれば同じ計算へ入れる。

## 2a. 初回設定と、本の週・食べる週・調理日の対応 — 2026-11-08追加
初回に次を家庭設定として保存する。実際の値は家庭データに置き、公開文書には転記しない。

| 設定 | 意味 |
| --- | --- |
| 食べる週の基準開始日 | 実日付の月曜と、対象とする曜日/食事。平日5日と7日を区別する |
| 本の基準位置 | その実日付の週へ対応付ける献立シリーズ/本の第何週か/巡回位置 |
| 調理予定 | 対象の食べる週に向けた土日等の日付、1日/連続2日の選択 |
| 以後の進め方 | 基準から暦の週数で順に進める。シリーズ/対象曜日の変更は有効な開始週付きで行う |

「1週間」の日付範囲が5日間と読める場合、7日分を勝手に追加しない。月曜開始の週IDと食べる対象の曜日を分け、5日設定ではその曜日の予定だけを採用する。本の7日分を5日に詰め直したり、除外した料理を翌週へ自動的に回したりしない。調理が土日であることと、食べる対象に土日を含むかは別の設定である。

本の同じ献立を使う第1週と第3週でも、テンプレートの同一性と巡回の位置は別に保持する。基準の実週をW0、その本の位置をp0とし、対象週との差を7日単位で求めて位置を解決する。日付計算は日本時間の暦日を用いる。本の「何週目」を暦月の第何週か、生年月日からの経過日数、アプリ起動/プレビュー/保存回数から推定しない。家族の別端末で開いても進行位置を進めない。

例として4週の対応がA/B/A/Bなら、基準週の位置と経過週数で翌週の候補を解決する。同じパターンを何回目に使うかも追跡できる。利用を一週飛ばした場合も、開く回数で順番がずれない。順番を止めて再開したい場合やシリーズを変更する場合は、以後に効く基準を明示して変更し、過去の計画を再割当しない。

プロフィールの月齢表示/食事段階と、本の献立シリーズ/巡回位置を分ける。誕生日や暦月の切替だけで別シリーズへ変更しない。次の月齢向けへ進める時は家庭が選び、その開始週を保存する。将来この進行を自動化する場合も、家庭が選んだルールと登録済み内容に従う機能として別途扱い、医学的な自動判断に置き換えない。

### 最初に開く対象
- 「きょう」は実際の今日と、今日属する食べる週を表示する。
- 献立/買い物/つくるを準備目的で開くときは、設定した調理周期に対応する「次に準備する食べる週」を初期対象とする。土日調理の対象を、その土日が属する週と取り違えない。普段の準備で毎回「翌週へ」を押させることを標準にしない。
- 買い物から調理/出来高登録まで、作業中の対象週を固定する。日付や画面をまたいだだけで別週へ移さない。次の準備サイクルへ移るときに、保存した設定と次の対象週を解決する。
- 手動で過去/別の週を見た操作はタブの閲覧状態として扱い、家庭の基準設定や他端末の表示を変更しない。閲覧した古い週が、次回の通常の準備開始の既定値へ残り続けないようにする。
- 前の作業が未完了なら、その続きと次の準備対象を区別する。未完了週を無断で上書き/移動したり、黙って別週の調理記録へ保存したりしない。

画面の共通見出しに「食べる期間」「調理予定日」「本のシリーズ/第何週」を同時に表示する。相対的な「今週/翌週」だけを対象確認の根拠にしない。予定・材料・工程・出来高登録は同じ対象週/計画版を参照する。土日をまたぐ調理でも対象の食べる週を変えず、実際の作成日と期限は各ロットに保持する。食べる週の末日を冷凍期限として自動設定しない。

### 内容の準備と既存記録
最初に使うシリーズの巡回パターンを必要な範囲で登録・検証する。出典の位置を概観できたことと、全パターンの材料/工程が利用可能であることは別。指定位置の定義が未登録の場合に、別の週や前週を同じものとして代用しない。初期実装は代表週の固定ではなく、家庭が選んだ開始位置と通常の翌週の準備が成立する範囲を優先する。

採用した各週に、実日付・テンプレートID/版・本の位置と適用基準を保持する。初期設定変更や月替わりで採用済みの週を再生成しない。既に手動で選択された週はそのまま残し、テンプレートへの置換は明示した操作とする。今回の家庭の開始日/対象曜日/本の初回位置は確認前であり、設定済みとして扱わない。

## 3. 分離するデータ
| 層 | 保持する内容 |
| --- | --- |
| 出典付きの週間テンプレート | 料理/使用回数、食べる時の追加食品、出典と版、対象段階の目安 |
| 調理の定義 | 共通ベース/工程の入力と産出、仕上げ材料、1回分、量の基準、調理条件、確認状態 |
| 家庭の週間計画 | 採用したテンプレートの版、料理の差替え/外食、調理日数/方法 |
| 計画計算の結果 | 需要、期限内在庫の引当、不足、予定出来高/余剰、材料、日別工程、計算根拠 |
| 現物と実績 | 実際の完成品ロット・作成/冷凍日・期限、使用/廃棄/訂正、料理のお気に入り、材料チェック |

テンプレートや調理定義を更新しても、以前のロットの1回分・レシピ版・期限や実績の意味を変えない。日常の内容追加はコード再配備を不要とする既存方針を維持。主利用者にBOMや係数の手入力を日々求めず、AIが資料を構造化し、登録/確認する保守操作を普段の操作から分ける。既存の家庭記録を初期化しない。

## 4. 必要量計算の順序
1. 変更後の食事予定を、料理と使用日ごとの需要へ集計する。外食/不要の食事は対象外。食事時の追加食品も予定データとして保持し、曜日の固定表から無関係な食品を補わない。
2. 使用日まで期限内で状態/単位が対応する完成品ロットを、全週の予定へ重複なく引き当てる。過去の未記録予定は将来の在庫を予約し続けない。
3. 不足する料理だけを仕上げの需要とし、共通ベースの所要量と、その料理だけに加える材料へ分ける。
4. 同じ定義/調理方法/状態で互換なベースの需要を合算し、上流の材料と共通工程を計画する。食材名が同じだけでは混ぜず、同じ材料でも状態や用途を保持する。
5. 登録した最小量/最大量/実行単位がある工程だけ、その理由に従って計画を丸める。残る量は仕込みの未配分分や明示した完成品の余剰として説明し、無関係な料理を勝手に作成対象へ足さない。
6. 仕込み材料と、食事時に用意する食品を集約して必要量を表示する。その後、材料の有無チェックで買う対象を選ぶ。
7. 確定した計画量を使い、下処理・機器の占有・共通加熱・配分・仕上げ・小分けを1日/連続2日へ組む。完成前の料理は在庫にしない。
8. 実出来高/使用が記録された時点で現物在庫を更新し、不足を再計算する。計画変更だけでは現物を増減しない。

計算は登録データから再現できる処理とし、日々の計画ごとに生成AIへ判断させない。初回は既知の料理群への明示的な共同計画ルールで成立させ、汎用最適化エンジンや企業向けERPの導入を条件にしない。

## 5. 共通ベース・複数産出物
計算上は同日工程の中間物を扱うが、利用者に中間素材の在庫を登録させない。

架空の例として、同じベースから料理甲と料理乙を仕上げる場合、甲3回・乙2回なら共通ベースは計5回分。甲1回・乙4回へ変えても、両者の1回分が同じベース量なら共通ベースは計5回分のままで、乙だけに使う仕上げ材料を変更する。本の元の仕上げ比率を固定したり、甲/乙それぞれにベース全量を計上したりしない。この例は本の分量や実調理指示ではない。

一つの加熱から具材とスープなど複数の産出物が得られる場合、普通の単一出力BOMだけでは扱えない。下流の必要量、同時にできる量、配分残を揃えて確認する。具材を減らしても同じ量/性質のスープが得られるとは仮定しない。スープを新しい購入食材や水と同一視して二重計上しない。調理用の水と、料理へ取り分けるスープも分ける。

量の変更を扱うルールが不足する場合は、その工程の算出済み量と未確認条件を区別する。既存の共同仕込みの代替方法/調整範囲を整備し、未選択料理の全量製造で問題を隠さない。日をまたぐ素材保存を標準の解決策にしない。

## 6. 1回分の係数と調理条件
資料が示す投入量、産出物の配分率、仕上げへの投入量、回数を対応付け、1回分の所要量へ正規化する。係数に出典、分母、原材料/下処理後/加熱後/完成品などの基準を付ける。分数は計算の終わりまで保持し、表示丸めを途中の計算へ戻さない。

次を混同しない。
- 元の週間例の予定出来高と、実際に測った歩留まり。
- 加熱後の産出物の半量と、その加熱後のg数。
- 正味の材料重量と、皮等を含む購入重量。
- 完成品1回分と、容器1個/食品の個数。
- 材料量の按分と、加熱時間/水量/機器条件の変更。

元の週間出来高を固定ロットにする方法は撤回。少量で機器が動かない等の実際の制約は、該当工程の最小量と理由として別に持つ。レコルト等の登録された方法は機種/投入範囲/運転単位を守り、同名の本の料理と出来高や1回分を自動的に同一換算しない。

素材量の計算上の根拠と、調理の適用範囲の確認を分けて進める。資料にない条件を生成して全条件で実調理済みとは表示しない。全料理の単品レシピを探すことを、共通仕込みの設計の代わりにしない。

## 7. 在庫と調達量の範囲
完成品は使用日/期限/状態・1回分の対応を踏まえて数量で差し引く。作り方や版が違うロットは、家庭の1回分の互換性が確認できる範囲で扱い、同じ名前だけで同量としない。

原材料は2026-11-07の主利用者レビューどおり「今回の必要分がある/買う」を維持する。必要量は数値で計算するが、手持ちのg数を入力させたり、未入力の残量を推測して不足gを算出したりしない。少しだけ持っている材料は、必要量を見て買う側に残せる。「ある」は少量の現物の存在だけではなく、表示した必要分を賄えるという判断に使う。

したがって初回の買い物表示は「完成品在庫を差し引いた調理の材料必要量」と「買う対象」であり、原材料の厳密な数量残高から引く方式ではない。正確な原材料の差引量が必要になった場合は入力負担を含む要件変更として判断し、今回のMRPという比喩だけを理由にグラム在庫を再導入しない。

| D4 NAS統合 | 内容/家庭データの版・保存と移行、更新 | 既存記録保持、再読込/家族共有、更新/復旧の条件を満たす |

代表ケース：
- 基準週と本の巡回位置の対応、同じパターンの繰返し位置、複数端末/再読込/利用しない週があっても順番がずれないこと。
- 土日調理の準備対象、金曜/日曜/月曜・月替わりの境界、5日/7日設定で、食べる期間/材料/工程/出来高登録が同じ計画を参照すること。
- 本の開始位置/シリーズを変更しても過去の計画が変わらず、未登録のパターンへ無言で別の週を割り当てないこと。
- 元の週間テンプレートの再現。
- 同じ共通ベース総量で仕上げの比率だけ変更。
- 一つの料理を候補/お気に入りへ差替え、不要な仕上げ材料・工程だけが外れる。
- 外食の指定で、その食事の冷凍品と追加食品の需要が外れる。
- 完成品が一部残る場合/使用日に期限を超える場合/複数週から予約する場合。
- 1品だけ・全食外食・不足ゼロで、全セットが自動追加されない。
- 機器の最低量/運転単位で余剰が生じる場合、理由と行き先が示される。
- 家電方法へ替える場合、旧材料と新材料/工程が二重に残らない。
- 2日で作る場合、前日に未作成の中間物を参照せず、予定と現物を混ぜない。
- 作成済みの後に献立を変えても、作った在庫や過去実績を巻き戻さない。
- 定義/出典不足を0扱いや隠れた全セット製造で埋めない。
- 内容版の更新やアプリ更新で、過去の食事ID・履歴・ロットの意味を保持する。

D1/D2が成立する前に画面だけを直してNASへ再配備しない。まず代表の一週間と現実的な数か所の変更で計算を成立させ、対象を増やす。NAS/認証/外部接続を再構築せず、既に確認できた基盤とUIは再利用する。目的と家庭専用の制約は維持し、P2〜P4の中核計画と順序を改訂する。ローンチ/実調理の完了を今回の設計策定で代替しない。
